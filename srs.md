Software Requirements Specification (SRS)Project Title: Real-Time Threat & Anomaly Detection EngineVersion: 1.01. System ArchitectureThe System is a decoupled backend service comprising four primary components:API Layer (Flask & Flask-SocketIO): REST endpoints and WebSocket channels for high-throughput data ingestion without blocking.Message Broker (Redis): Asynchronous queues (video_stream, network_stream) to decouple fast data ingestion from slow ML inference.Inference Workers (Celery / Python Multiprocessing): Dedicated background processes executing the CNN, KNN, and ANN models independently of the Flask main thread.Persistence Layer (SQLite/PostgreSQL): Stores flagged anomalous events, model drift metrics, and system trends.2. Functional Requirements2.1 API Ingestion LayerFR-1.1: The Flask application shall expose a WebSocket endpoint (via Flask-SocketIO) at /ws/stream/video for continuous ingestion of binary frame data.FR-1.2: The Flask application shall expose a POST endpoint at /api/v1/network/log to receive JSON-formatted network telemetry.FR-1.3: The API process shall strictly NOT run model inference. It must instantly validate and enqueue payloads to Redis.2.2 Inference Workers & ML PipelineFR-2.1: Background workers shall load the CNN (.h5), ANN (.h5), and KNN (.pkl) models only once at startup to prevent severe disk I/O latency during stream processing.FR-2.2: The CNN worker shall process video frames and output a fixed-length spatial feature embedding.FR-2.3: The KNN worker shall compute the geometric distance from incoming network logs to the nearest normal baselines.FR-2.4: The ANN fusion worker shall consume both the CNN embedding and KNN distance within a configurable temporal window (e.g., 2.0 seconds) to produce a final risk score between 0.0 and 1.0.2.3 Results & AlertingFR-3.1: Workers shall publish inference results back to a Redis pub/sub channel.FR-3.2: The System shall flag events scoring $\ge 0.7$ as Anomalies and write them to the database.3. Data & Model Schemas3.1 Model Artifact InterfaceCNN Model: spatial_cnn.h5 (Deep Learning - Keras). Input: 224x224 RGB float32 tensor; Output: Feature vector.KNN Model: network_knn.pkl (Machine Learning - scikit-learn). Fitted Pipeline utilizing StandardScaler and KNeighborsClassifier.ANN Model: fusion_ann.h5 (Deep Learning - Keras). Input: Concatenated CNN and KNN numerical outputs; Output: Sigmoid activation score representing unified threat level.3.2 Database Schema (Events Table)SQLCREATE TABLE events (
  event_id       INTEGER PRIMARY KEY AUTOINCREMENT,
  source_id      TEXT NOT NULL,
  captured_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  risk_score     REAL NOT NULL,
  severity       TEXT NOT NULL, 
  knn_distance   REAL,
  cnn_score      REAL
);
4. Non-Functional RequirementsNFR-1 (Latency): API receive-to-enqueue latency shall be $\le 20$ ms at p95. End-to-end inference latency (from data receipt to ANN score generation) shall be $\le 500$ ms.NFR-2 (Reliability): A worker crash shall only drop the currently processing chunk. Unacknowledged tasks in Redis must be safely redelivered.NFR-3 (Decoupling): The Flask API must remain responsive regardless of the CPU load generated by the ML/DL inference workers.
